# 代码规范

当前项目第一阶段采用 Vue 3、Vite、TypeScript、Node.js、NestJS、PostgreSQL、Redis/BullMQ、Prisma、pnpm workspace、本地磁盘存储和 Docker Compose。

- 代码变更必须对应 OpenSpec change。
- 实现前必须阅读相关 change 的 proposal、specs、design、review、tasks 和 plan。
- 业务逻辑、外部接口、调度任务和 AI 调用应保持边界清晰。
- 敏感配置通过环境变量或密钥管理。
- 核心业务规则必须有自动化测试。
- AI 安全边界、排行榜、提醒名单和打卡状态流转必须有测试覆盖。
- 排行榜计算、提醒扫描/重试、管理员作废和企业微信周榜消息属于核心业务逻辑，新增或修改时必须先补自动化测试。
- AI 文本解析、健康安全分类、咨询日志、文件上传和附件删除策略属于核心隐私/安全逻辑，新增或修改时必须先补自动化测试。
- `.codex/skills/**`、`docs/**`、`openspec/**` 不参与 TypeScript 编译、lint、测试和打包。
- 共享类型、状态枚举和 API 契约优先放在 `packages/shared`，避免前后端重复定义。
- 第一阶段保留单管理员 auth 占位和 AI adapter 模块边界；企业微信身份识别以智能机器人入站 `userid` 和 Excel 名册导入为准，不保留企业微信 OAuth、自建应用或通讯录同步代码路径。
- 数据库命令按环境区分：`dev:db:*` 只用于本地开发和演示初始化；生产环境不得使用 `prisma db push`，应使用迁移任务（例如 `prisma migrate deploy`）和幂等 bootstrap/seed 任务完成结构升级与基础数据写入。
- 数据库升级必须考虑兼容发布：涉及字段替换、枚举状态或数据迁移时，优先采用“先加新结构、兼容读写、迁移数据、再移除旧结构”的多阶段方案。
- Docker 镜像构建应尽量减少构建期网络依赖：依赖安装集中在 `pnpm install --frozen-lockfile`，后续 `pnpm deploy --prod` 使用 `pnpm --offline` 复用 BuildKit pnpm store；API 构建使用 `tsc -p tsconfig.json`，不依赖 `@nestjs/cli`。
