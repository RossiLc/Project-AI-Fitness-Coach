# 机器人架构与流程图

本文档沉淀 Open Fit 当前稳定的企业微信机器人设计。早期讨论中的单机器人、URL 回调、企业微信自建应用、通讯录同步和 webhook 群机器人方案不再作为当前实现路径。

## 总体架构图

```mermaid
flowchart LR
  Employee["企业微信群员工"] -->|"@ 打卡助手 / @ AI 教练"| WeCom["企业微信智能机器人平台"]
  WeCom -->|"SDK 长连接 WebSocket"| Stream["WeComStreamBotService"]
  Stream -->|"归一化 text / image / mixed + botRole"| Bot["WeComBotService"]

  Bot -->|"botRole=checkin"| CheckinFlow["打卡助手流程"]
  Bot -->|"botRole=coach"| CoachFlow["AI 教练流程"]

  CheckinFlow --> Attachments["受控图片附件"]
  CheckinFlow --> Checkins["CheckinsService"]
  CheckinFlow --> AiVision["AI 图片/图文识别"]
  Checkins --> DB["PostgreSQL"]
  Attachments --> Storage["本地文件存储"]

  CoachFlow --> GuardrailIn["输入安全围栏"]
  GuardrailIn --> Conversation["CoachConversationService"]
  Conversation --> AiProvider["OpenAI-compatible AI Provider"]
  AiProvider --> GuardrailOut["输出安全围栏"]
  GuardrailOut --> DB

  Admin["Web 单管理员工作台"] -->|"选择当前群"| Groups["群管理"]
  Groups --> DB
  Admin -->|"提醒未打卡"| Reminder["RemindersService"]
  Reminder -->|"sendMessage(chatid)"| Stream
```

## 双机器人职责边界

```mermaid
flowchart TB
  UserMsg["群内 @ 机器人消息"] --> Role{"机器人来源"}

  Role -->|"Open Fit 打卡助手"| CheckinBot["打卡助手"]
  Role -->|"Open Fit AI 教练"| CoachBot["AI 教练"]
  Role -->|"无法识别"| SafeDefault["保守按 AI 教练处理，不写入打卡"]

  CheckinBot --> CheckinOnly["只处理打卡、补图、打卡状态、群绑定口令"]
  CheckinOnly --> NoAdvice["不回答训练咨询，不查询活动规则"]
  CheckinOnly --> MustImage["正式打卡必须包含图片凭证"]

  CoachBot --> AdviceOnly["只处理训练建议、活动规则、活动信息、排行榜查询"]
  AdviceOnly --> NoCheckin["不创建打卡，不修改打卡记录"]
  AdviceOnly --> Safety["输入/输出双向安全围栏"]
```

设计原则：

- 打卡会写入数据库，误判成本高，因此不能让一个机器人同时承担“打卡入库”和“开放咨询”。
- 入口本身就是业务上下文：员工找打卡助手就是提交运动记录，找 AI 教练就是咨询或查询。
- 如果长连接适配层无法识别机器人来源，默认走 AI 教练路径，并禁止写入打卡。

## 群绑定与成员初始化流程

```mermaid
sequenceDiagram
  participant Admin as Web 管理员
  participant Web as Web 群管理
  participant API as API 群服务
  participant DB as PostgreSQL
  participant Group as 企业微信群
  participant Bot as Open Fit 打卡助手

  Admin->>Web: 新增群
  Web->>API: 创建待绑定群
  API->>DB: 保存 WeComGroup(bindCode)
  API-->>Web: 返回绑定口令 OF-XXXXXX
  Admin->>Group: @Open Fit 打卡助手 绑定群 OF-XXXXXX
  Group->>Bot: 发送群消息，携带 chatid 和 from.userid
  Bot->>API: 长连接入站事件
  API->>DB: 按 bindCode 写入 chatid
  API-->>Bot: 回复群绑定成功
  Admin->>Web: 上传 Excel 名册
  Web->>API: 导入 userId、姓名、部门
  API->>DB: 按 userid upsert Member 和 WeComGroupMember
```

当前产品不依赖企业微信通讯录 Secret。成员中文名和部门来自管理员导入的 Excel 名册；机器人入站消息只稳定依赖 `from.userid`。

## 打卡助手流程

```mermaid
flowchart TD
  Start["员工 @ Open Fit 打卡助手"] --> Bind{"是否绑定群口令"}
  Bind -->|"是"| BindGroup["绑定当前群 chatid"]
  BindGroup --> ReplyBind["回复绑定成功"]

  Bind -->|"否"| Type{"消息类型"}
  Type -->|"text-only"| NeedImage["提示补发图片，不创建打卡"]
  Type -->|"image-only"| ImageAI["调用 AI 图片识别"]
  Type -->|"mixed 图文混排"| MixedAI["文字优先 + 图片凭证，调用 AI 综合识别"]

  ImageAI --> Complete{"运动类型/时长/消耗能量完整"}
  MixedAI --> Complete
  Complete -->|"完整"| Save["创建 submitted 有效打卡，关联 active 图片附件"]
  Complete -->|"不完整"| AskMore["提示补充缺失字段，不入库"]

  Save --> ReplyOK["回复打卡成功"]
  NeedImage --> End["结束"]
  AskMore --> End
  ReplyOK --> End
```

打卡规则：

- 正式企业微信打卡必须有图片凭证。
- text-only 不创建正式打卡，只提示补图。
- image-only 或 mixed 必须调用真实 AI 识别；业务代码不得用固定默认值或本地公式伪造运动类型、时长或热量。
- AI 推断字段完整时直接提交，不再要求员工回复“确认”。
- 打卡助手不读取 AI 教练上下文，避免历史咨询影响打卡入库。

## AI 教练咨询流程

```mermaid
flowchart TD
  Start["员工 @ Open Fit AI 教练"] --> Identify["识别 orgId + chatid + userid"]
  Identify --> Clear{"是否清空上下文口令"}
  Clear -->|"是"| ClearCtx["删除当前会话上下文，保留用户画像"]
  ClearCtx --> ReplyClear["回复已清空"]

  Clear -->|"否"| InputGuard["输入安全围栏"]
  InputGuard --> InputAllowed{"输入是否通过"}
  InputAllowed -->|"否"| SafeReject["直接安全提示，不调用模型，不写入会话"]
  InputAllowed -->|"是"| Intent{"查询类型"}

  Intent -->|"活动规则/活动信息"| Activity["读取当前群 active 活动内容"]
  Intent -->|"排行榜查询"| Leaderboard["读取当前群排行榜"]
  Intent -->|"训练/饮食咨询"| Context["读取最近 10 条消息 + 滚动摘要 + 长期用户画像"]

  Activity --> Model["调用真实 AI Provider 或生成规则回答"]
  Leaderboard --> Model
  Context --> Model

  Model --> OutputGuard["输出安全围栏"]
  OutputGuard --> OutputAllowed{"输出是否通过"}
  OutputAllowed -->|"否"| Replace["替换为安全提示，不保存模型原文"]
  OutputAllowed -->|"是"| SaveCtx["保存用户问题和安全回答"]
  SaveCtx --> Reply["回复企业微信"]
  Replace --> Reply
```

AI 教练记忆策略：

- 群聊会话按 `orgId + chatid + 企业微信 userid` 隔离；单聊按 `orgId + 企业微信 userid` 隔离。
- 每次模型调用只注入最近 10 条消息和滚动摘要。
- 短期会话 3 天未互动后不再注入；超过 30 天未更新的会话记录由服务启动清理。
- 长期结构化用户画像不自动过期，不因“清空上下文”删除。
- 输出安全围栏未通过时，不把模型原文发给用户，也不写入会话历史。

## 后台提醒未打卡流程

```mermaid
sequenceDiagram
  participant Admin as Web 管理员
  participant Web as 成员管理
  participant API as RemindersService
  participant DB as PostgreSQL
  participant Stream as WeComStreamBotService
  participant Group as 企业微信群

  Admin->>Web: 在当前群点击“提醒未打卡”
  Web->>API: POST /api/admin/reminders/scan 或提醒接口
  API->>DB: 查询当前群成员
  API->>DB: 查询今日 submitted/corrected 有效打卡
  API->>API: 计算未打卡名单
  API->>DB: 读取当前群 chatid
  alt 群已绑定 chatid
    API->>Stream: 打卡助手 sendMessage(chatid, markdown)
    Stream->>Group: 群内 @ 未打卡 userid
    API->>DB: 记录提醒任务和发送状态
    API-->>Web: 返回发送结果
  else 群未绑定 chatid
    API-->>Web: 提示先在目标群绑定打卡助手
  end
```

提醒规则：

- Web 后台所有运营动作以当前群为边界。
- 未打卡提醒只发送到当前群，不做个人应用消息。
- 消息内容基于当前群未打卡成员的企业微信 `userid` 进行 @。
- 如果当前群没有绑定 `chatid`，提醒功能必须明确提示先完成群绑定。

## 数据与模块关系图

```mermaid
flowchart LR
  WeComGroup["WeComGroup\n群、chatid、bindCode"] --> GroupMember["WeComGroupMember\n群成员关系"]
  Member["Member\nuserid、姓名、部门"] --> GroupMember
  Member --> Checkin["Checkin\n运动类型、时长、热量、状态"]
  Checkin --> Attachment["Attachment\n图片相对路径、MIME、状态"]
  Checkin --> Recognition["RecognitionResult\nAI 识别结果"]
  WeComGroup --> Activity["Activity\n活动周期、活动内容"]
  Activity --> Checkin
  Activity --> Leaderboard["LeaderboardSnapshot / Entry"]
  Member --> Conversation["CoachConversation\n短期会话摘要"]
  Conversation --> Message["CoachConversationMessage\n最近消息"]
  Member --> Profile["CoachProfileMemory\n长期结构化画像"]
```

核心边界：

- `WeComGroup.chatId` 是群内主动推送的目标。
- `Member.wecomUserid` 是员工身份主键来源。
- `Activity.ruleJson.content` 是 AI 教练回答活动规则和活动信息的知识来源。
- `Attachment.localPath` 只保存本地相对路径，图片访问必须走后端受控文件路由。
- `CoachConversation` 是短期上下文，不是永久聊天归档；`CoachProfileMemory` 是长期结构化画像。
