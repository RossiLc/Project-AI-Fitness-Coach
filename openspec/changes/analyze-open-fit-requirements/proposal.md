## 为什么

Open Fit 当前处于需求草案阶段，已经覆盖企业微信机器人、Web 打卡平台、AI 识别、排行榜、定时任务、提醒和健康咨询等多个方向。若直接进入实现，容易出现范围漂移、企业微信能力边界误判、健康建议合规风险和数据隐私遗漏。

本变更先用 `spec-driven-superpowers` 建立需求分析与技术调研基线，把产品能力、技术边界、风险、任务和后续执行计划沉淀为中文 OpenSpec 产物，为后续 MVP 实现提供清晰入口。

## 做什么

- 梳理 Open Fit 的产品范围、角色、核心流程和能力边界。
- 调研企业微信机器人、自建应用消息、Web 打卡、AI 识别、排行榜和提醒流程的技术可行性。
- 明确健康、饮食、运动咨询的安全边界与免责声明要求。
- 建立项目长期知识库体系，明确入口文件、渐进式加载规则和需求闭环回写机制。
- 建立项目级 `.codex/skills/`，让 OpenSpec 与 Superpowers 以 `runtime-backed` 方式结合。
- 形成后续 MVP 实现前需要补充确认的问题清单和执行计划。

## 成功标准

- 项目具备中文化的 OpenSpec + spec-driven-superpowers 工作流基础设施。
- 需求分析产物覆盖企业微信机器人和 Web 打卡平台两条主线。
- 明确哪些能力由群机器人完成，哪些能力更适合企业微信自建应用。
- 识别一组 MVP 优先级、关键风险和待确认问题。
- 建立可被 Agent 渐进式加载的项目知识库，并明确每次需求结束后的知识库回写规则。
- `.codex/skills/` 中保留项目级 Superpowers 运行时资产，避免依赖单个开发者电脑的全局安装。
- 后续可以基于本变更继续创建“实现 MVP”的 OpenSpec 变更。

## 不做事项

- 本变更不实现企业微信机器人、Web 服务、数据库、AI 调用或定时任务代码。
- 本变更不确定最终技术栈，只给出调研倾向和选型约束。
- 本变更不提供医疗诊断、康复处方或个性化治疗建议。
- 本变更不接入真实企业微信凭证或员工数据。

## 影响范围

- `wecom-fitness-coach`：企业微信 AI 健身教练机器人能力，包括群内咨询回复、每日小贴士和每周排行榜推送。
- `workout-checkin-platform`：Web 运动打卡平台能力，包括文本/图片打卡、AI 识别、结构化记录和用户确认。
- `fitness-analytics-reminders`：运动数据统计、排行榜、仪表盘和未打卡提醒能力。
- `health-advice-safety`：健康、饮食、运动咨询的安全边界、免责声明、风险升级和隐私约束。
- `project-knowledge-system`：项目长期知识库、Agent 入口文件、渐进式加载、Superpowers 运行时优先和需求闭环回写能力。

## 影响文件

- OpenSpec 工作流配置与中文模板。
- 根目录 Agent 入口文件和项目 README。
- `docs/知识库/` 长期知识库。
- `.codex/skills/` 项目级 Codex 技能目录。
- 后续企业微信机器人服务、Web 后端、前端仪表盘、AI 识别服务、任务调度、数据库设计和通知流程。

## 待确认问题

- 企业微信组织内是否允许创建群机器人和自建应用？
- 是否已有员工身份系统、部门信息和企业微信 userid 映射？
- 运动打卡是否每日一次，是否允许补卡、撤销和管理员修正？
- 是否需要活动周期、团队赛、积分规则或奖励规则？
- 图片是否可能包含人脸、办公环境或其他敏感信息，是否需要脱敏、有效期清理和访问控制？
